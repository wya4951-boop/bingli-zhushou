# 病历助手

将按床号整理的查房摘要转换为适用于一般住院科室的中文日常病程草稿，供医生审核修改。

## 功能

- 提供本地文件夹路径后自动读取 Markdown（`.md`）或纯文本（`.txt`）每日汇总，支持最新日期、指定日期或日期范围。

- 按固定床号区分患者，确认出院后重置当前患者上下文。
- 首次使用需提供患者所在科室；未提供时先询问，已确认且未变化时无需重复。
- 非血液科移植病房采用通用病程格式，不要求或生成移植日期、移植日数。
- 仅血液科移植病房启用移植计日：单日移植当天记为0d、次日+1d；双日移植分别记为01d和02d，第二次移植结束后的次日记为+1d。
- 区分事件发生时间、消息报告时间、已执行处理及待执行计划。
- 按每日病程结构检查完整性，允许有依据的模板句式和中性开头、结尾；必要缺项集中列出供医生补齐。
- 仅分析已有症状，新增的用药关联分析与病程正文分开。
- 缺失资料不自动补全，不把未报告体温写成无发热。

## 文件结构

```text
SKILL.md
agents/openai.yaml
references/clinical-writing.md
references/daily-note-quality.md
scripts/transplant_day.py
tests/test_transplant_day.py
```

`SKILL.md`定义工作流程；`references/clinical-writing.md`定义文风；`scripts/transplant_day.py`执行日期计算；`agents/openai.yaml`提供显示名称和默认提示语。

## 本地安装与使用

将仓库下载并解压，将含有`SKILL.md`的根目录命名为`bingli-zhushou`，放入所使用客户端的个人skills目录。Codex可使用`~/.agents/skills/bingli-zhushou/`。避免解压后多套一层目录。

输入`$bingli-zhushou`并提供患者所在科室、床号、每日摘要和记录日期；血液科需明确是否为移植病房。仅血液科移植病房模式需按实际情况补充移植类型和实际移植日期。新患者或患者出院时明确说明床号和状态。若客户端尚未显示技能，可重新启动后检查。

移植日期脚本仅使用Python标准库，需要Python 3.8+运行环境；非移植模式不调用该脚本。客户端需具备读取参考文件的能力，移植计日时还需执行脚本的能力。

## 从文件夹自动读取

客户端必须具备访问该本地文件夹的能力。首次提供路径和科室，例如：

> 使用 $bingli-zhushou。科室为消化内科，请从我提供的本地文件夹读取最新每日汇总，生成病程草稿。文件夹路径：〈在当前聊天填写实际路径〉。

同一聊天后续可直接说“生成最新病程”或“读取指定日期的汇总生成病程”，无需重复路径及未变化的科室设置。血液科需明确是否为移植病房，移植计日仍需实际回输日期。

默认只检查目录直属的 `.md`、`.txt` 文件，以正文日期及统计区间核对最新每日汇总，不按修改时间选取；不将历史专题汇总或已生成病程当作当天输入。同日互补资料保留各自来源并去重，有冲突的版本先核实。指定日期不存在时会说明缺失，跨午夜事件按实际事件日期整理。读取过程不修改原文。

这是每次请求时的自动读取，不是后台定时监控。若客户端无法访问该目录，需要提供可访问的文件或粘贴文本。

实际路径只在当前任务中使用，不写入技能、README、全局记忆或GitHub；源文件及患者内容也不得提交到仓库。本地读取会把必要文本提供给当前助手处理，并不意味着全程离线。新聊天需要重新提供路径。

## 完整病程与模板使用

每天按当日状态或治疗阶段、症状与一般情况、客观资料、医生评估、处理及计划检查完整性。已有信息写成连贯正文，缺失的必要内容放在正文外“待补充／核实”；未补齐前仍是待审核草稿。

“未记录”不等于“无症状”或“正常”。原文明示的阴性症状、正常检查，或负责医生确认的当日具体正常项目可以写入；笼统的“无特殊不适”不展开为全部查体或检验正常。全无当日资料时提示补充，不生成全正常病程。

允许使用“据当日资料，患者……”等中性开头，并在正文外以“待医生核对补充”收尾。“病情平稳”“今日查房”“继续原治疗”等含有临床事实或医嘱的句子，需要当日依据。

通用行文规则和完全虚构示例见 `references/clinical-writing.md`。原始模板不提交到GitHub；只提取不含身份、真实床号、日期链、机构、病史组合或检验参数的通用结构，不以简单替换姓名代替脱敏。

## 修改

修改流程、输出或患者管理规则时编辑`SKILL.md`；修改文风时编辑`references/clinical-writing.md`；计日规则变化时同步修改日期脚本。修改后使用完全虚构的输入验证结果。

## 数据边界

本仓库仅包含通用规则、日期工具及完全虚构示例，不包含真实病例、原始参考文档、患者或医务人员身份、真实床号实例、患者日期链及聊天记录。不要把实际患者资料提交到本仓库。

运行时的患者资料与skill包分开。当前版本没有独立患者数据库，不自动签名或写入正式病历。生成结果为待审核草稿，不能替代临床医生判断。
